## 1. 产品概述

### 1.1 一句话定位

面向高压工作人群的 **AI + 健康管理应用**，聚焦 **饮食健康** 与 **睡眠健康** 两大场景，用 AI Agent 建立"**无感采集 → 智能评估 → 最小可执行微行为 → 形成正循环**"的健康习惯。

### 1.2 产品理念

- **零焦虑**：不做卡路里焦虑式记账，用"七大要素"质感饮食诊断 + 热量模糊估算（适中/偏高区间）替代精算扣减。
- **重陪伴**：AI Agent 按全天生理节律主动陪伴（晨间唤醒/餐前/久坐/午后低谷/睡前），柔性提醒、最小补救动作，不制造骚扰。

### 1.3 产品目标

1. 用户用 **最少的操作、零焦虑** 完成饮食与睡眠记录（拍照识食、语音记录、一键快捷录入）。
2. 用 **AI 深度分析** 取代纯数据看板，以"七大要素"质量诊断 + 能量量化双视角输出"人话"结论与建议。
3. 通过 **多端通知 + Agent 主动干预** 完成健康管理的最后一步（执行与反馈），形成闭环而非"孤岛数据展示"。
4. 数据 **本地优先、云端同步**，严格保护隐私健康数据。
5. 以 **微行为养成** 代替硬性约束：3-5 分钟拉伸、一口水、一次深呼吸，驱动正循环。

### 1.4 核心差异化（对竞品）

| 竞品通病 | 本产品解法 |
|---|---|
| 止步于"告诉你缺蛋白" | 做到"缺蛋白 → 生成午餐补缺任务 → 锁屏提醒 → 反馈回流"的完整闭环 |
| 精算卡路里制造焦虑 | 七大要素质量诊断 + 模糊估算区间 |
| 记录摩擦大、流失快 | 拍照/语音/一句话 3 种零摩擦入口 |
| 无干预触达 | 手机推送 + 锁屏 Rich Notification + 穿戴设备通知（后期） |

## 2. 目标用户与典型场景

| 用户类型 | 特征 | 核心诉求 | 关键使用场景 |
|---|---|---|---|
| 普通用户（上班族/健身人群） | 关注体重管理与饮食质量 | 记录方便、看得懂、提醒及时 | 早餐拍照识食；久坐被提醒拉伸 |
| 深度用户 | 长期减重/增肌/控糖 | 个性化能量目标、闭环干预 | 跨餐补缺任务；运动时序规划 |
| 健康关注者 | 睡眠不佳、作息紊乱 | 睡眠评分、睡前干预 | 晨间身体电量；睡前降噪 |
| 潜在付费用户 | 对深度 AI 分析有需求 | 高级教练、深度报告 | 订阅会员 |

**三个核心用户故事：**

1. **作为上班族小李**，我早上拍一张早餐照片，3 秒内就能知道这餐质量如何、缺什么；中午打卡前系统提醒我"早餐缺蛋白，午餐优先选鸡胸肉/牛肉"——我不需要懂营养学，也能吃对。
2. **作为熬夜患者小王**，我起床看到"身体电量 42%（亏空预警）"卡片，今日高强度运动被自动替换为慢走与拉伸，早餐收到"补优质蛋白抗疲劳"策略——系统先保命再谈进步。
3. **作为深度用户小张**，我每晚收到"准备睡眠"提醒，一键进入助眠播客；次日睡眠周报告诉我"高糖晚餐与深睡减少相关"——我看到了因果，而不是一串数字。

### 4.3 饮食记录（FR-DIET）

| 编号 | 功能描述（用户视角） | 优先级 |
|---|---|---|
| FR-DIET-01 | **拍照识食**：拍摄/上传食物照片，AI 识别食物种类与份量，生成能量分析；识别结果页支持份量修正、显示置信度 | P0 |
| FR-DIET-02 | **文字/语音记录**：如"一碗牛肉面加一个卤蛋"，AI 解析为结构化条目 | P0 |
| FR-DIET-03 | **食物库检索**：内置 ≥10 万条食物库（含中国常见食物），支持模糊搜索 | P0 |
| FR-DIET-04 | **扫码录入**：扫描包装食品条形码，调取商品营养信息 | P1 |
| FR-DIET-05 | 按早餐/午餐/晚餐/加餐分类记录，支持自定义餐次 | P0 |
| FR-DIET-06 | 每餐 **AI 营养点评**：能量合理性、营养素缺口、升糖影响、食材搭配建议 | P0 |
| FR-DIET-07 | **能量分析报告**：周/月能量趋势、热量来源占比、进食时序分布、超量预警 | P0 |
| FR-DIET-08 | "克制模式"模板：间歇断食 16:8、控糖、低脂等 | P1 |
| FR-DIET-09 | 食谱收藏、常用餐一键复录 | P1 |
| FR-DIET-10 | 饮水记录（手动/快捷打卡） | P2 |
| FR-DIET-11 | **早餐"三要素"专项诊断**：①优质蛋白（蛋/奶/豆浆/豆制品）②优质低 GI 碳水（番薯/玉米/燕麦/全麦 vs 精制碳水）③膳食纤维/蔬果；缺项给出解释（如"缺蛋白上午易提早饥饿与血糖波动"） | P0 |
| FR-DIET-12 | **七大营养要素结构化诊断**：每次记录输出优质蛋白/优质碳水/膳食纤维/脂肪质量/水分/维生素矿物质七项完成度 | P0 |
| FR-DIET-13 | **热量模糊估算**：仅提供"适中/偏高"区间参考，不做强制精确扣减，降低焦虑 | P1 |
| FR-DIET-14 | **营养缺口跨餐记账**：缺口自动计入当日账本，下一餐打卡前 Agent 主动提示补缺方案（如"午餐缺蛋白，晚餐建议优先鸡胸肉/牛肉"） | P0 |
| FR-DIET-15 | **饮食档案"起居注"**：按日期复查历史每餐照片、营养评价与改善建议 | P1 |
| FR-DIET-16 | **智慧饮水**：按体重计算每日目标（如 2000ml），超时未打卡触发提醒 | P1 |

**关键业务规则：**
- 拍照识食结果必须可人工修正（份量 ± 调整），修正行为回流为训练样本。
- 识别置信度 <90% 时，结果页提示用户确认或改用文字/语音补充描述。
- 识别失败/离线时，自动降级为文字/语音手动记录（P0 独立入口，不依赖拍照）。

**验收标准（抽样）：** 10 张真实食物照片单种识别准确率 ≥90%、份量估算误差 ≤30%；"一碗牛肉面加一个卤蛋"解析字段完整率 100%。

| FR-SLEEP-07 | 睡眠-饮食关联分析：如"高糖晚餐后的深睡减少"趋势洞察 | P1 |

|---|---|---|

| FR-RHYTHM-04 | **注意力与生物钟匹配**：结合 HRV 与疲劳数据，下午低谷期（约 15:00）提醒 3 分钟深呼吸 | P2 |
| FR-RHYTHM-05 | **饭后散步与血糖稳态提醒（12:00-14:00）**：午餐打卡后提示散步 10-20 分钟平抑血糖波动 | P2 |
| FR-RHYTHM-06 | **午休充电方案（12:00-14:00）**：引导选择"30 分钟小睡"或"15 分钟降压冥想"，结束后温和鼓励 | P2 |
| FR-RHYTHM-07 | **晚间运动与用餐时序规划（18:00-23:00）**：按运动安排校准时间窗口；前夜睡眠差时自动将高强度运动替换为瑜伽/慢走/拉伸 | P2 |
| FR-RHYTHM-08 | **睡前无缝降噪（22:30-23:30）**：睡前 30 分钟触发准备睡眠通知，一键调起助眠内容（第三方：小宇宙播客/白噪音/冥想） | P1 |

**设计原则：** 所有提醒遵循"柔性提醒 + 最小补救动作"（久坐提醒附 2 分钟拉伸入口、饮水提醒附一口温水建议），不制造焦虑。

### 4.6 AI Agent（FR-AGENT）

**Agent 角色划分：**

| Agent | 职责（用户视角） | 触发场景 |
|---|---|---|
| 营养师 Agent | 帮我解析每餐、评估营养质量、补缺、推荐食谱 | 每次饮食记录后；我提问时 |
| 睡眠教练 Agent | 帮我分析睡眠、找原因、睡前干预、起床窗口 | 每日睡眠同步后；睡前提醒时 |
| 健康管家 Agent | 跨域调度（饮食×睡眠）、任务编排、通知文案、记忆维护 | 汇总/闭环衔接时 |

| 编号 | 功能描述 | 优先级 |
|---|---|---|
| FR-AGENT-01 | 多模态理解：图片（食物照片）、语音、文字 3 种输入统一解析 | P0 |
| FR-AGENT-02 | 工具调用：食物库检索、营养计算、用户档案、历史记录、通知发送等 | P0 |
| FR-AGENT-03 | 个性化记忆：长期（偏好/忌口/过敏/目标）+ 短期（近期行为），用户可查看/删除记忆 | P0 |
| FR-AGENT-04 | 主动建议：记录后、餐点前、睡前等关键时点主动产出建议 | P0 |
| FR-AGENT-05 | 建议可执行化：每条建议必须结构化（任务标题/时间/可完成动作），可生成干预通知 | P0 |
| FR-AGENT-06 | 反馈学习：完成/忽略/纠正行为回流，更新建议策略 | P1 |
| FR-AGENT-07 | 风险护栏：识别极端饮食/厌食倾向/疾病相关提问时，输出免责声明并建议就医 | P0 |
| FR-AGENT-08 | 对话式追问：分析结果支持"为什么""怎么办"多轮追问 | P0 |
| FR-AGENT-09 | 跨域推理：饮食×睡眠关联（如咖啡因与深睡）、联动建议 | P1 |
| FR-AGENT-10 | 延迟要求：分析响应 P95 ≤5s；生成任务与通知 P95 ≤8s | P1 |

**闭环验收红线（产品级）：** 系统中不存在"孤岛数据"——每一条记录必须有 AI 处理痕迹，每一条建议必须能追踪到用户反馈或干预结果。一条"记录→分析→建议→通知→反馈"闭环全链路 ≤10s 可见。

## 7. 验收标准与上线红线

**功能验收（抽样）：**

| 验收项 | 通过标准 |
|---|---|
| 拍照识食 | 10 张真实照片，单种识别准确率 ≥90%，份量误差 ≤30% |
| 语音/文字解析 | "一碗牛肉面加一个卤蛋"字段完整率 100% |
| 早餐三要素 | 达标场景三项全 ✓；缺蛋白场景输出解释 + 跨餐补缺建议 |
| 闭环链路 | 记录→分析→建议→通知→反馈 ≤10s 可见 |
| 防亏空 | 电量 <50% 日正确降级运动建议 + 营养补偿 |
| 锁屏通知 | 卡片与快捷动作正常，深色/浅色模式正常 |
| 免打扰 | 静默时段（22:00-08:00）零通知 |

**上线红线（不可妥协）：**
1. 健康合规：免责声明 + 风险护栏 + 法务评审通过
2. 隐私：授权流程完整、本地优先默认开启、注销可删除
3. 数据闭环：不允许存在无 AI 处理痕迹的"孤岛记录"
