**交互机制要点**：
1. **同步链路**（REST/WebSocket）：客户端 ↔ 网关 ↔ 业务服务，Agent 流式输出经 WebSocket；
2. **异步链路**（事件驱动）：业务服务发布领域事件至 Kafka，Agent 订阅后异步分析，分析结果经通知服务回调用户；
3. 跨服务事务采用 **Saga + 事件补偿**，禁止分布式事务强一致（TCC 仅限支付域）；
4. 所有服务经网关对外，内部服务间默认 mTLS（见安全架构图）。

## 4. Agent 编排图 (Agent Orchestration)

多 Agent 协作与工具调用（SRS 第 5 章）。

```mermaid
flowchart TB
    EVT[领域事件<br/>food.recorded / sleep.synced / task.feedback] --> ORCH[健康管家 Agent<br/>编排器 Orchestrator]

    ORCH -->|场景路由| NUT[营养师 Agent]
    ORCH -->|场景路由| SLP[睡眠教练 Agent]
    NUT --> TOOL1[食物库检索]
    NUT --> TOOL2[营养计算引擎<br/>Mifflin-St Jeor/BMR]
    SLP --> TOOL3[睡眠结构分析]
    SLP --> TOOL4[归因规则引擎]
    ORCH --> TOOL5[用户档案与记忆<br/>RAG]
    ORCH --> TOOL6[任务与通知工具<br/>创建 MVMB/推送]

    NUT --> ORCH
    SLP --> ORCH
    ORCH -->|产出| TASK[AgentTask<br/>结构化建议]
    ORCH -->|产出| MEM[AgentMemory 更新]
    ORCH -->|产出| NOTICE[通知模板]

    GUARD[AI 合规护栏<br/>输入脱敏/输出审核/免责] -.-> NUT
    GUARD -.-> SLP
    GUARD -.-> ORCH
```

**编排策略**：
- **编排者模式**：健康管家 Agent 作为 orchestrator 完成跨域推理（饮食×睡眠关联，FR-AGENT-09）与任务编排；
- 每个 Agent 为**有界工具使用者**，只能调用职责范围内的工具；
- Agent 输出必须(shall)经结构化校验（JSON Schema）后才可生成任务与通知。

```mermaid
    end

    subgraph sg272["服务端"]
        SYNC --> GW2[API 网关]
        GW2 --> DIETSVC[饮食服务]
        GW2 --> SLEEPSVC[睡眠服务]
        DIETSVC --> PG[(业务库)]
        SLEEPSVC --> PG
        DIETSVC -->|分析请求·脱敏| AGENTSVC[Agent 服务]
        AGENTSVC --> LLMAP[大模型 API<br/>不落盘]
        AGENTSVC --> VEC[(用户画像向量库)]
        DIETSVC -->|事件| MQ2[Kafka]
        MQ2 --> ARCH2[起居注服务]
        ARCH2 -->|每日汇总| DW2[(数仓)]
    end

    LOCAL -.可选上传.-> OBJ2[对象存储<br/>照片 90 天留存]
```

**数据流转规则**：
1. 原始照片与健康明细**默认本地优先**，仅结构化脱敏数据上云（FR-DATA-02）；
2. 大模型输入必须(shall)经脱敏（去身份标识），输出经合规审核，不使用用户数据训练第三方模型；
3. 数据留存：原始照片 90 天，分析结果永久（脱敏）；注销后 30 天内彻底删除（FR-DATA-04）。

## 7. 安全架构图 (Security & Compliance Architecture)

零信任模型与纵深防御。

```mermaid
graph TB
    subgraph sg302["终端信任域"]
        APPSEC[App 加固<br/>防逆向/防调试]
        KSC[本地密钥<br/>Keychain/Keystore]
        BIOM[生物识别<br/>Face ID/指纹]
    end

    subgraph sg308["边界信任域"]
        WAF[WAF<br/>SQLi/XSS/CC 防护]
        OIDC[OIDC/OAuth 2.0<br/>登录+授权]
        MFA[MFA 可选]
        JWT[JWT + Refresh Token<br/>短期/可吊销]
    end

    subgraph sg315["服务信任域"]
        MTLS[mTLS 服务间认证]
        RBAC[RBAC 权限模型]
        KMS[KMS 密钥管理<br/>AES-256 数据加密]
        AUDIT[审计日志<br/>不可篡改]
        RATE[限流/配额<br/>AI 接口按用户按天]
    end

    subgraph sg323["数据信任域"]
        TDE[数据库 TDE 加密]
        OBJENC[对象存储<br/>服务端加密]
        LOGENC[日志脱敏]
        RBAC2[列级访问控制<br/>敏感字段]
    end

    APPSEC --> OIDC
    BIOM --> KSC
    OIDC --> JWT
    JWT --> WAF
    WAF --> MTLS
    MTLS --> RBAC
    RBAC --> KMS
    KMS --> TDE
    RATE --> RBAC
    RBAC2 --> TDE
    AUDIT --> LOGENC
```

**安全基线**（映射 ISO/IEC 27002 控制项，详见技术架构书 §7）：
- 传输层：全链路 TLS 1.3（RFC 8446）；服务间 mTLS；
- 存储层：数据库 TDE + 敏感字段 AES-256 列级加密；密钥经 KMS 轮换管理；
- 身份：OIDC + JWT 短期令牌（建议 ≤15min）+ Refresh Token 轮换；健康数据接口设备级校验；
- 审计：全量操作审计日志，日志落盘前脱敏；
- 合规：等保二级起步、PIPL 合规处理、生成式 AI 服务备案与内容审核。
