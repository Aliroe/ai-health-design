    产品需求文档（PRD）「AI 健康伴侣」¶

    项目 内容
    文档编号 PRD-AIH-2026-001
    版本 V1.0
    编写日期 2026-08-09
    文档状态 评审稿
    关联文档 《软件需求规格说明书 V1.1》（SRS-AIH-2026-001）、原型 prototype/index.html（15 页）、《原型页面-功能清单 V1.3》
    说明 本文档为 SRS 的产品视角版本：以用户故事、功能描述与验收标准为主线；需求编号沿用 SRS 的 FR-[模块]-[序号]，技术规格（接口/数据字段/协议）以 SRS 为准

    1. 产品概述¶

    1.1 一句话定位¶

    面向高压工作人群的 AI + 健康管理应用，聚焦 饮食健康 与 睡眠健康 两大场景，用 AI Agent 建立"无感采集 → 智能评估 → 最小可执行微行为 → 形成正循环"的健康习惯。

    1.2 产品理念¶

    • 零焦虑：不做卡路里焦虑式记账，用"七大要素"质感饮食诊断 + 热量模糊估算（适中/偏高区间）替代精算扣减。
    • 重陪伴：AI Agent 按全天生理节律主动陪伴（晨间唤醒/餐前/久坐/午后低谷/睡前），柔性提醒、最小补救动作，不制造骚扰。

    1.3 产品目标¶

    1. 用户用 最少的操作、零焦虑 完成饮食与睡眠记录（拍照识食、语音记录、一键快捷录入）。
    2. 用 AI 深度分析 取代纯数据看板，以"七大要素"质量诊断 + 能量量化双视角输出"人话"结论与建议。
    3. 通过 多端通知 + Agent 主动干预 完成健康管理的最后一步（执行与反馈），形成闭环而非"孤岛数据展示"。
    4. 数据 本地优先、云端同步，严格保护隐私健康数据。
    5. 以 微行为养成 代替硬性约束：3-5 分钟拉伸、一口水、一次深呼吸，驱动正循环。

    1.4 核心差异化（对竞品）¶

    竞品通病 本产品解法
    止步于"告诉你缺蛋白" 做到"缺蛋白 → 生成午餐补缺任务 → 锁屏提醒 → 反馈回流"的完整闭环
    精算卡路里制造焦虑 七大要素质量诊断 + 模糊估算区间
    记录摩擦大、流失快 拍照/语音/一句话 3 种零摩擦入口
    无干预触达 手机推送 + 锁屏 Rich Notification + 穿戴设备通知（后期）

    2. 目标用户与典型场景¶

    用户类型 特征 核心诉求 关键使用场景
    普通用户（上班族/健身人群） 关注体重管理与饮食质量 记录方便、看得懂、提醒及时 早餐拍照识食；久坐被提醒拉伸
    深度用户 长期减重/增肌/控糖 个性化能量目标、闭环干预 跨餐补缺任务；运动时序规划
    健康关注者 睡眠不佳、作息紊乱 睡眠评分、睡前干预 晨间身体电量；睡前降噪
    潜在付费用户 对深度 AI 分析有需求 高级教练、深度报告 订阅会员

    三个核心用户故事：

    1. 作为上班族小李，我早上拍一张早餐照片，3 秒内就能知道这餐质量如何、缺什么；中午打卡前系统提醒我"早餐缺蛋白，午餐优先选鸡胸肉/牛肉"——我不需要懂营养学，也能吃对。
    2. 作为熬夜患者小王，我起床看到"身体电量 42%（亏空预警）"卡片，今日高强度运动被自动替换为慢走与拉伸，早餐收到"补优质蛋白抗疲劳"策略——系统先保命再谈进步。
    3. 作为深度用户小张，我每晚收到"准备睡眠"提醒，一键进入助眠播客；次日睡眠周报告诉我"高糖晚餐与深睡减少相关"——我看到了因果，而不是一串数字。

    3. 版本规划¶

    阶段 周期 范围 发布目标
    M1 需求与原型 2 周 本文档 + 原型走查 内部评审 ✅（已完成）
    M2 MVP 6 周 账号、饮食记录（拍照/语音）、能量分析、Dashboard、七要素基础诊断 核心记录与分析跑通
    M3 闭环 Beta 6 周 睡眠、Agent 任务、手机+锁屏通知、节律陪伴、反馈回流 闭环可见（记录→分析→建议→通知→反馈 ≤10s）
    M4 V1.0 6 周 七大要素完整诊断、起居注卡片、跨餐记账、报告、订阅 商业验证
    M5 后期 待定 手环/手表绑定与穿戴通知（Apple Watch/小米/华为/三星） 生态扩展

    4. 功能需求¶

    优先级定义：P0 必须（MVP 不可缺）/ P1 重要（Beta 补齐）/ P2 可选（后期或增强） 需求编号与 SRS 一一对应，便于研发对照技术规格。

    4.1 用户与初始化（FR-AUTH）¶

    编号 功能描述（用户视角） 优先级
    FR-AUTH-01 支持手机号/邮箱注册登录，支持微信/Apple/Google 一键登录 P0
    FR-AUTH-02 首次启动引导：填写身高/体重/年龄/性别/日常活动量及核心健康目标（抗疲劳/改善睡眠/控糖/增强精力/减重/增肌），生成个人基础档案 P0
    FR-AUTH-03 一键引导授权：通知权限、相机权限、健康数据（HealthKit/Health Connect）权限 P0
    FR-AUTH-04 首次同意隐私政策/用户协议，默认开启"本地优先"模式 P0
    FR-AUTH-05 支持家庭/多账号切换，可为家人代录饮食 P2
    FR-AUTH-06 手环/手表绑定与引导（后期开发）：Apple Watch / Wear OS / 小米 / 华为 / 三星，实现数据静默同步与设备通知 P2

    验收标准： 新用户从下载到完成首次早餐记录 ≤ 3 分钟；任意第三方登录失败时有手机号兜底路径。

    4.2 今日总览 Dashboard（FR-DASH）¶

    编号 功能描述（用户视角） 优先级
    FR-DASH-01 首屏展示今日"能量环"：已摄入 / 目标 / 剩余（或超出），带平滑动画 P0
    FR-DASH-02 展示营养素进度条：碳水/蛋白质/脂肪/膳食纤维（克数 + 百分比） P0
    FR-DASH-03 今日睡眠摘要卡片：睡眠评分、时长、深睡占比（穿戴或手动） P0
    FR-DASH-04 AI 今日洞察 1~3 条：一句话人话结论，点击进入 Agent 对话 P0
    FR-DASH-05 今日待办任务（Agent 生成），支持一键完成 P1
    FR-DASH-06 连续打卡/健康 streak 与勋章展示 P2
    FR-DASH-07 晨间"身体电量"卡片：电量 >80% 活力充足 / <50% 亏空预警 P1
    FR-DASH-08 每日"身体起居注"手帐卡片：自动汇总睡眠分/早餐完成度/七要素覆盖率/冥想拉伸饮水数据，可保存分享图片（含 Agent 寄语） P1
    FR-DASH-09 正向勋章体系："优质脂肪达人/早餐唤醒大师/深睡恢复大师/喝水达人"等成就解锁 P2

    验收标准： 首屏 2s 内完成加载（4G）；AI 洞察必须能追溯到对应分析记录，点击可进入对话追问。

    4.3 饮食记录（FR-DIET）¶

    编号 功能描述（用户视角） 优先级
    FR-DIET-01 拍照识食：拍摄/上传食物照片，AI 识别食物种类与份量，生成能量分析；识别结果页支持份量修正、显示置信度 P0
    FR-DIET-02 文字/语音记录：如"一碗牛肉面加一个卤蛋"，AI 解析为结构化条目 P0
    FR-DIET-03 食物库检索：内置 ≥10 万条食物库（含中国常见食物），支持模糊搜索 P0
    FR-DIET-04 扫码录入：扫描包装食品条形码，调取商品营养信息 P1
    FR-DIET-05 按早餐/午餐/晚餐/加餐分类记录，支持自定义餐次 P0
    FR-DIET-06 每餐 AI 营养点评：能量合理性、营养素缺口、升糖影响、食材搭配建议 P0
    FR-DIET-07 能量分析报告：周/月能量趋势、热量来源占比、进食时序分布、超量预警 P0
    FR-DIET-08 "克制模式"模板：间歇断食 16:8、控糖、低脂等 P1
    FR-DIET-09 食谱收藏、常用餐一键复录 P1
    FR-DIET-10 饮水记录（手动/快捷打卡） P2
    FR-DIET-11 早餐"三要素"专项诊断：①优质蛋白（蛋/奶/豆浆/豆制品）②优质低 GI 碳水（番薯/玉米/燕麦/全麦 vs 精制碳水）③膳食纤维/蔬果；缺项给出解释（如"缺蛋白上午易提早饥饿与血糖波动"） P0
    FR-DIET-12 七大营养要素结构化诊断：每次记录输出优质蛋白/优质碳水/膳食纤维/脂肪质量/水分/维生素矿物质七项完成度 P0
    FR-DIET-13 热量模糊估算：仅提供"适中/偏高"区间参考，不做强制精确扣减，降低焦虑 P1
    FR-DIET-14 营养缺口跨餐记账：缺口自动计入当日账本，下一餐打卡前 Agent 主动提示补缺方案（如"午餐缺蛋白，晚餐建议优先鸡胸肉/牛肉"） P0
    FR-DIET-15 饮食档案"起居注"：按日期复查历史每餐照片、营养评价与改善建议 P1
    FR-DIET-16 智慧饮水：按体重计算每日目标（如 2000ml），超时未打卡触发提醒 P1

    关键业务规则： - 拍照识食结果必须可人工修正（份量 ± 调整），修正行为回流为训练样本。 - 识别置信度 <90% 时，结果页提示用户确认或改用文字/语音补充描述。 - 识别失败/离线时，自动降级为文字/语音手动记录（P0 独立入口，不依赖拍照）。

    验收标准（抽样）： 10 张真实食物照片单种识别准确率 ≥90%、份量估算误差 ≤30%；"一碗牛肉面加一个卤蛋"解析字段完整率 100%。

    4.4 睡眠健康（FR-SLEEP）¶

    编号 功能描述（用户视角） 优先级
    FR-SLEEP-01 自动同步穿戴设备睡眠数据（深睡/浅睡/REM/清醒/入睡起床时间）；无设备支持手动记录，数据标注来源 P0
    FR-SLEEP-02 睡眠评分：基于时长/结构/规律性/睡眠-能量关联计算 0-100 分 P0
    FR-SLEEP-03 睡眠结构图（可交互）：各阶段时间线与占比 P0
    FR-SLEEP-04 AI 睡眠分析：归因分析（睡前饮食、咖啡因、运动、屏幕时间对睡眠的影响），输出可执行建议 P0
    FR-SLEEP-05 睡前提醒：自定义"准备睡眠"提醒（含明日计划卡片） P0
    FR-SLEEP-06 起床窗口：浅睡眠阶段窗口唤醒提醒 P1
    FR-SLEEP-07 睡眠-饮食关联分析：如"高糖晚餐后的深睡减少"趋势洞察 P1
    FR-SLEEP-08 睡眠日报/周报，可分享为健康卡片 P1
    FR-SLEEP-09 晨间"防亏空"保护机制：身体电量 <50% 时自动叫停剧烈运动安排，推送舒缓冥想与当日营养补偿策略（如"今日早餐补充优质蛋白抗疲劳"） P1
    FR-SLEEP-10 运动计划动态安全护栏：支持输入每周运动想法（如每周 3 次跑步），Agent 评估合理性；检测连续高压/高心率/低睡眠时强制降级为恢复性微行为（泡脚/拉伸/慢走） P1
    FR-SLEEP-11 运动与用餐时序规划：饭后 ≥2h 再运动、晚餐不晚于 20:00、运动不晚于 22:00 P2

    关键业务规则（安全红线）： 身体电量 <50% 时"高强度运动不可执行"为确定性硬约束，不随 AI 生成内容改变；降级同时必须给出营养补偿策略。

    4.5 全天候节律陪伴（FR-RHYTHM）¶

    编号 功能描述（用户视角） 优先级
    FR-RHYTHM-01 晨间唤醒 Routine（07:00-07:30）：闹钟后生成身体电量与睡眠洞察；电量 >80% 推荐 3-5 分钟活力拉伸/觉醒冥想；<50% 触发防亏空保护 P1
    FR-RHYTHM-02 通勤健康卡片（07:30-09:00）：对接权威资讯（如中国营养学会）推送每日健康卡片 P2
    FR-RHYTHM-03 久坐与站立交替提醒（09:00-12:00 / 14:00-18:00）：连续久坐 1 小时触发柔性提醒 + 2-5 分钟椅上拉伸指导动画 P1
    FR-RHYTHM-04 注意力与生物钟匹配：结合 HRV 与疲劳数据，下午低谷期（约 15:00）提醒 3 分钟深呼吸 P2
    FR-RHYTHM-05 饭后散步与血糖稳态提醒（12:00-14:00）：午餐打卡后提示散步 10-20 分钟平抑血糖波动 P2
    FR-RHYTHM-06 午休充电方案（12:00-14:00）：引导选择"30 分钟小睡"或"15 分钟降压冥想"，结束后温和鼓励 P2
    FR-RHYTHM-07 晚间运动与用餐时序规划（18:00-23:00）：按运动安排校准时间窗口；前夜睡眠差时自动将高强度运动替换为瑜伽/慢走/拉伸 P2
    FR-RHYTHM-08 睡前无缝降噪（22:30-23:30）：睡前 30 分钟触发准备睡眠通知，一键调起助眠内容（第三方：小宇宙播客/白噪音/冥想） P1

    设计原则： 所有提醒遵循"柔性提醒 + 最小补救动作"（久坐提醒附 2 分钟拉伸入口、饮水提醒附一口温水建议），不制造焦虑。

    4.6 AI Agent（FR-AGENT）¶

    Agent 角色划分：

    Agent 职责（用户视角） 触发场景
    营养师 Agent 帮我解析每餐、评估营养质量、补缺、推荐食谱 每次饮食记录后；我提问时
    睡眠教练 Agent 帮我分析睡眠、找原因、睡前干预、起床窗口 每日睡眠同步后；睡前提醒时
    健康管家 Agent 跨域调度（饮食×睡眠）、任务编排、通知文案、记忆维护 汇总/闭环衔接时
    编号 功能描述 优先级
    FR-AGENT-01 多模态理解：图片（食物照片）、语音、文字 3 种输入统一解析 P0
    FR-AGENT-02 工具调用：食物库检索、营养计算、用户档案、历史记录、通知发送等 P0
    FR-AGENT-03 个性化记忆：长期（偏好/忌口/过敏/目标）+ 短期（近期行为），用户可查看/删除记忆 P0
    FR-AGENT-04 主动建议：记录后、餐点前、睡前等关键时点主动产出建议 P0
    FR-AGENT-05 建议可执行化：每条建议必须结构化（任务标题/时间/可完成动作），可生成干预通知 P0
    FR-AGENT-06 反馈学习：完成/忽略/纠正行为回流，更新建议策略 P1
    FR-AGENT-07 风险护栏：识别极端饮食/厌食倾向/疾病相关提问时，输出免责声明并建议就医 P0
    FR-AGENT-08 对话式追问：分析结果支持"为什么""怎么办"多轮追问 P0
    FR-AGENT-09 跨域推理：饮食×睡眠关联（如咖啡因与深睡）、联动建议 P1
    FR-AGENT-10 延迟要求：分析响应 P95 ≤5s；生成任务与通知 P95 ≤8s P1

    闭环验收红线（产品级）： 系统中不存在"孤岛数据"——每一条记录必须有 AI 处理痕迹，每一条建议必须能追踪到用户反馈或干预结果。一条"记录→分析→建议→通知→反馈"闭环全链路 ≤10s 可见。

    4.7 通知与触达（FR-NOTIFY / FR-NTF）¶

    编号 功能描述 优先级
    FR-NOTIFY-01 应用内通知中心：聚合所有 AI 消息与系统提醒，已读/未读 P0
    FR-NOTIFY-02 系统推送（PUSH）：APNs/FCM，App 退出后可达 P0
    FR-NOTIFY-03 锁屏通知（Rich Notification）：锁屏直接展示能量剩余、营养素缺口、AI 建议卡片（含图片缩略），适配深色/浅色 P0
    FR-NOTIFY-04 锁屏快捷动作（Quick Actions）："直接记录午餐"/"稍后提醒"/"跳过" P1
    FR-NOTIFY-05 通知分组与免打扰时段（如 22:00-08:00 静默） P0
    FR-NOTIFY-06 通知智能降噪：同一类通知 N 次未被点击则降频或转周报聚合 P1
    FR-NOTIFY-07 穿戴设备通知（后期开发）：能量剩余、目标达成、久坐/睡眠提醒 P2
    FR-NOTIFY-08 通知模板与文案 A/B 测试（Agent 生成文案，运营配置） P2
    FR-NOTIFY-09 柔性防打扰文案与补救动作 P1
    FR-NTF-01 通知中心统一编排：事件→模板→通道→投放时间→去重合并 P0
    FR-NTF-02 智能投放时间：学习用户用餐/作息，避开打扰 P0
    FR-NTF-03 锁屏通知动态文案与图片（餐后照片缩略、能量环缩略图） P0
    FR-NTF-04 每条通知可追溯来源，提供"不再提醒此类" P0
    FR-NTF-05 免打扰三级控制：全局/时段/按类别（饮食、睡眠、AI 闲聊） P0
    FR-NTF-06 穿戴通知静音/震动/连续提醒策略配置（后期开发） P2
    FR-NTF-07 通知送达/点击/转化埋点，用于降噪与效果评估 P1

    文案规范： 由 Agent 生成 + 模板兜底；语气正面、具体、可执行（"距离目标还差 320 kcal，晚餐推荐：清蒸鲈鱼+糙米饭"）；禁止制造焦虑、禁止夸大健康承诺；医疗类建议一律附带免责声明。

    4.8 数据与隐私（FR-DATA）¶

    编号 功能描述 优先级
    FR-DATA-01 健康数据本地加密存储（iOS Keychain / Android Keystore），云端传输 TLS 1.3 P0
    FR-DATA-02 "本地优先"模式：不上传原始照片与健康明细，仅上传脱敏统计 P0
    FR-DATA-03 支持导出个人数据（JSON/CSV/PDF 健康报告） P1
    FR-DATA-04 支持注销账号并 30 天内彻底删除数据 P0
    FR-DATA-05 数据留存策略：原始照片 90 天，分析结果永久（脱敏后） P1
    FR-DATA-06 最小化采集：仅采集实现功能所需字段，告知用户用途 P0

    6. 非功能要求（产品视角）¶

    维度 目标
    性能 首屏 ≤2s（4G）；拍照识食 P50 ≤3s、P95 ≤8s；AI 对话首字 ≤2s；闭环全链路 ≤10s 可见

    离线 核心记录功能离线可用，联网后同步

    免责 医疗类建议一律附带免责声明（本应用不构成医疗诊断）

    7. 验收标准与上线红线¶

    功能验收（抽样）：

    验收项 通过标准
    拍照识食 10 张真实照片，单种识别准确率 ≥90%，份量误差 ≤30%
    语音/文字解析 "一碗牛肉面加一个卤蛋"字段完整率 100%
    早餐三要素 达标场景三项全 ✓；缺蛋白场景输出解释 + 跨餐补缺建议
    闭环链路 记录→分析→建议→通知→反馈 ≤10s 可见
    防亏空 电量 <50% 日正确降级运动建议 + 营养补偿
    锁屏通知 卡片与快捷动作正常，深色/浅色模式正常
    免打扰 静默时段（22:00-08:00）零通知

    上线红线（不可妥协）： 1. 健康合规：免责声明 + 风险护栏 + 法务评审通过 2. 隐私：授权流程完整、本地优先默认开启、注销可删除 3. 数据闭环：不允许存在无 AI 处理痕迹的"孤岛记录"

    8. 风险与对策¶

    风险 影响 对策
    食物识别准确率不足 核心体验 份量二次确认 + 人工修正 + 数据回流训练 + 文字/语音降级入口
    大模型成本失控 毛利 缓存/降级规则/每日配额/小模型分级
    通知骚扰导致卸载 留存 智能降噪 + 免打扰 + 柔性文案 + 用户可配置
    穿戴设备生态割裂 覆盖（后期） 推迟至 M5，先手机端验证价值；先接 iOS Watch + 1 个主流手环
    健康合规风险 法律 免责声明、风险护栏、双法务评审

    9. 附录：术语表¶

    术语 说明
    能量 食物总热量与营养素（碳水/蛋白/脂肪/膳食纤维）的综合能量画像
    能量缺口 当日摄入热量与目标热量的差值
    七大要素 优质蛋白、优质碳水、膳食纤维、脂肪质量、水分、维生素与矿物质的质感饮食诊断框架
    身体电量 基于睡眠/HRV/疲劳度综合评估的当日精力值（0-100%）
    防亏空保护 睡眠或精力亏空时，Agent 自动降级高强度安排并给出营养补偿策略
    起居注 每日自动汇总的健康手帐卡片与可按日期回查的饮食档案
    闭环 采集→分析→建议→干预→反馈→再采集 的完整循环
    锁屏通知 手机锁屏界面直接展示的丰富通知（Rich Notification）
