    产品协作工作台 SOP（飞书 / 钉钉可复用模板）¶

    项目 内容
    文档编号 SOP-AIH-2026-001
    适用范围 AI 健康伴侣 产品-设计-研发-测试 全流程协作
    兼容平台 飞书 / 钉钉（结构一致，附录含两端落地点位对照）
    使用方式 直接复制本文档到飞书知识库 / 钉钉知识库，按章节建群建表

    0. 工作台总体架构¶

    工作台（飞书/钉钉 团队空间）
├── 01 项目作战室（群组）
│   ├── 全体群（通知）
│   ├── 产品群（PRD/原型评审）
│   ├── 研发群（技术/联调）
│   └── 数据与运营群（埋点/反馈）
├── 02 知识库（文档中心）
│   ├── 需求库（PRD / 原型 / 调研报告）
│   ├── 设计库（UI 规范 / 组件 / 交互稿）
│   ├── 技术库（架构 / 接口文档 / Agent Prompt 资产）
│   └── 复盘库（里程碑复盘 / 用户反馈）
├── 03 项目计划（任务与看板）
│   ├── 迭代计划表（周维度）
│   ├── 需求看板（待评审/已评审/开发中/测试/验收/已上线）
│   └── 里程碑追踪表（M1-M4）
├── 04 自动化（机器人）
│   ├── 需求变更通知机器人
│   ├── 每日站会汇总机器人
│   ├── 构建/发布通知机器人
│   └── 健康指标周报机器人
└── 05 文档模板库（本章节 4-8 可直接复制使用）

    1. 角色与职责（RACI）¶

    角色 核心职责 对应成员
    产品经理 PM 需求定义、优先级、验收标准、跨组协调 产品负责人
    产品运营 PO 用户调研、数据埋点需求、通知文案审核 运营
    交互/UI 设计 原型、UI 规范、走查 设计
    客户端开发（iOS/Android） App 功能、锁屏通知、穿戴 SDK 接入 研发
    服务端开发 API、通知中心服务、数据存储 研发
    AI 工程 大模型接入、Agent 编排、视觉识别、Prompt 资产 AI 研发
    测试 QA 功能/闭环链路/兼容性/性能测试 测试
    项目经理 PMO（可选） 里程碑节奏、风险跟进 项目负责人

    2. 核心流程 SOP¶

    SOP-1 需求生命周期（从想法到上线）¶

    输入 → 需求池 → 需求评审 → 排期 → 开发 → 验收 → 上线 → 复盘
 │       │
 │       └─(飞书/钉钉: 需求表按状态流转)
 │
 ├─ 1.1 需求收集
 │    · 来源：用户反馈群/竞品调研/数据/老板/脑暴
 │    · 模板：见 §4 需求卡片
 │    · 动作：PM 每周五 18:00 前将新需求入「需求池」并打优先级 P0/P1/P2
 │
 ├─ 1.2 需求评审（每周二 14:00 例会）
 │    · 前置：PRD + 原型 提前 24h 发评审群
 │    · 通过标准：功能/交互/数据埋点/通知策略/验收标准 五要素齐全
 │    · 结论：评审通过 → 移入「已评审」；打回 → 标注原因，一周内重新提交
 │
 ├─ 1.3 开发与联调
 │    · 每个需求必须有验收标准（Given-When-Then 或 清单式）
 │    · 涉及 Agent 的必须提交 Prompt 资产到知识库
 │
 ├─ 1.4 测试验收
 │    · 验收清单模板见 §6
 │    · 闭环链路必须全链路验证（记录→分析→建议→通知→反馈）
 │
 └─ 1.5 上线与复盘
     · 发布窗口：每周四（留周五兜底）
     · 上线后 48h 内：监控埋点（DAU/记录数/通知点击率）
     · 每里程碑：一次复盘会（§7 模板）

    SOP-2 每周节奏（固定例会）¶

    时间 会议 时长 要点
    周一 10:00 周计划会 30min 本周目标、任务认领、风险
    周二 14:00 需求评审会 60min 新需求评审（SOP-1）
    周三 11:00 设计走查 30min 原型/UI 走查
    周四 18:00 发版确认 15min 上线内容冻结
    周五 17:30 周复盘 30min 完成度、问题、下周预告

    SOP-3 闭环需求验收红线（本产品特有）¶

    任何功能如果属于以下三类，验收时必须提供闭环证据，否则视为未完成：

    ① 记录类：记录 → 有 AI 分析结果（入库可见）→ 有建议产出
② 建议类：AI 建议 → 可追踪到任务 → 可追踪到通知 → 可追踪到用户反馈
③ 通知类：通知 → 有送达/点击埋点 → 有点赞/跳过可回流 Agent 记忆

    SOP-4 变更管理¶

    • 任何变更（需求/排期/技术方案）由发起人在需求表更新状态并 @ 相关人。
    • 变更幅度超 1 人日 → 走一次 15min 变更确认（同步建文档留痕）。
    • 变更必须同步更新：PRD、验收标准、接口文档、Prompt 资产。

    3. 落地清单：飞书 / 钉钉 端到端搭建¶

    3.1 飞书版¶

    步骤 操作
    1. 建群 新建 5 个群（见 §0 架构），全员拉入「全体群」
    2. 建知识库 飞书「云文档」→ 新建知识库「AI健康伴侣」，按 §0 建目录
    3. 建多维表格 创建「需求池」多维表格：状态/优先级/负责人/评审日期/验收标准/闭环证据
    4. 建看板 多维表格切换「看板视图」，按状态分组
    5. 机器人 创建自定义机器人：需求状态变更→群通知；每日 09:55 站会提醒
    6. 日历 建共享日历「产品研发节奏」，录入 §2 例会
    7. 文档模板 把 §4-§8 模板复制进知识库「文档模板库」

    3.2 钉钉版¶

    步骤 操作
    1. 建群 新建「项目作战室」1 个总群 + 按需子群（产品/研发/数据）
    2. 建知识库 钉钉「知识库」→「AI健康伴侣」，按 §0 建目录
    3. 建表格 钉钉「多维表格」→ 需求池（字段同飞书）
    4. 看板 多维表格「看板视图」
    5. 机器人 群「自定义机器人」（加签模式）：状态变更通知；「定时提醒」每天站会
    6. 日历/日程 团队日程共享，录入例会
    7. 待办 每个迭代用「待办」圈人分配任务，关联多维表格记录

    3.3 两平台功能对照¶

    能力 飞书 钉钉
    知识库 云文档知识库 知识库
    需求管理 多维表格 多维表格
    看板 多维表格看板视图 多维表格看板视图
    机器人 自定义机器人（Webhook） 自定义机器人（加签）
    自动化 工作流（审批/提醒） 工作流（审批/提醒）
    视频会议 飞书会议 钉钉会议
    审批 审批应用 审批应用

    9. 使用说明¶

    1. 团队 < 5 人：只需「全体群 + 需求池表 + 周会/复盘 + 文档库」，其余按需裁剪。
    2. 模板均为通用结构，任何产品线可复制复用；将文档名中的「AI健康伴侣」替换即可。
    3. 机器人/自动化逐步接入，第一周先人工，第二周起启用状态变更通知，避免一上来被通知淹没。
    4. 所有模板允许团队自行增删，但「SOP-3 闭环验收红线」与「需求五要素」不可删（产品核心原则）。
