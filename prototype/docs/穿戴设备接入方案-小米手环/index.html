    穿戴设备接入方案 · 小米手环（第一期）¶

    配套需求：SRS FR-AUTH-06（手环/手表绑定）、FR-SLEEP-01（睡眠数据同步）、FR-NOTIFY-07（穿戴通知）｜里程碑 M5 状态：方案定稿，等待开发排期 更新时间：2026-08

    1. 结论先行（选型建议）¶

    小米手环没有面向普通开发者的公开健康数据 API。 官方「小米健康云开放平台」只对小米生态链企业及合作伙伴开放（申请 AppID/AppKey 需商务合作），独立/初创团队短期无法拿到。

    因此推荐主通道是：

    「小米运动健康 App → 系统健康数据平台 → 我们的 App」

    • Android 手机：Health Connect（Google 官方健康数据中枢，小米手机内置支持）
    • iOS 手机：Apple HealthKit（小米运动健康 iOS 版支持写入睡眠/心率/步数）

    手环通知则走系统通知镜像：用户把我们的 App 加进小米运动健康的「应用通知」列表，手环自动震动提醒，无需任何厂商 API。

    对比项 ① 系统健康平台（推荐） ② 小米健康云开放平台 ③ 蓝牙直连（Gadgetbridge）
    资质要求 无（Google Play 账号 + 隐私声明） 生态链企业/商务合作 无
    官方性 官方标准通道 官方（但拿不到） 非官方（逆向协议）
    数据范围 步数/睡眠/心率/HRV 等 全量历史数据 全量（协议级）
    稳定性 高（随 Android/iOS 版本演进） 高 低（协议变动即失效）
    通知能力 系统通知镜像 ✓ 有 ✓
    适合阶段 MVP / V1.0 规模化后商务申请 不推荐正式产品

    2. 推荐方案架构¶

    ┌──────────┐   蓝牙    ┌──────────────────────┐   云/本地    ┌────────────────────┐
│ 小米手环  │◄────────►│  小米运动健康 App      │◄───────────►│  Health Connect     │
│ (7/8/9…) │           │（用户自装，负责采集）   │  写入        │  / Apple HealthKit  │
└──────────┘           └──────────────────────┘              └─────────┬──────────┘
                                                                       │ 读取（授权后）
                                                              ┌────────▼──────────┐
                                                              │  我们的 App        │
                                                              │ ┌────────────────┐ │
                                                              │ │ 数据同步服务      │ │ ← WorkManager 定时拉取
                                                              │ │ 归一化层(睡眠/心率)│ │ ← 字段→七要素映射
                                                              │ │ AI Agent 分析    │ │ ← 评分/建议/通知
                                                              │ └────────────────┘ │
                                                              └───────────────────┘

    核心设计原则： 1. 不直连手环 BLE——采集交给小米运动健康，我们只读系统健康平台，工作量最小、稳定性最高。 2. 统一数据模型——在服务端定义统一睡眠/心率/步数模型，兼容后续华为、vivo（见 §8）。 3. 用户授权制——每次拉取前检查授权状态，取消授权后立即停止拉取并本地清除。

    3. 实际操作步骤（Android + iOS 双端）¶

    3.1 准备阶段¶

    # 事项 说明
    1 注册 Google Play 开发者账号 $25 一次性，Health Connect 权限声明必须
    2 注册 Apple Developer 账号 $99/年，HealthKit 真机调试需要
    3 准备真机 一台小米/红米手机（装 Health Connect 与小米运动健康）+ 一台 iPhone（iOS 16+）+ 小米手环 7/8/9
    4 准备小米运动健康账号 用户侧需登录并绑定手环；开发测试可用自己的小米账号
    5 编写隐私政策 必须声明：采集数据类型、用途、不向第三方出售
    6 技术栈决策 原生 Android(Kotlin)/iOS(Swift)，或 Flutter（社区包 health 同时封装 Health Connect + HealthKit）

    3.2 Android（Health Connect）¶

    ① 添加依赖（build.gradle）：

    dependencies {
    implementation "androidx.health.connect:connect-client:1.2.0-alpha04"
}

    ② 声明权限（AndroidManifest.xml），按需声明读取的类型：

    <uses-permission android:name="android.permission.health.READ_SLEEP"/>
<uses-permission android:name="android.permission.health.READ_HEART_RATE"/>
<uses-permission android:name="android.permission.health.READ_STEPS"/>
<uses-permission android:name="android.permission.health.READ_RESTING_HEART_RATE"/>

    ③ 请求授权（引导用户到 Health Connect 授权页）：

    val healthConnectClient = HealthConnectClient.getOrCreate(context)

// 声明需要读的数据类型（睡眠、心率、步数）
val permissions = setOf(
    HealthPermission.getReadPermission(SleepSessionRecord::class),
    HealthPermission.getReadPermission(HeartRateRecord::class),
    HealthPermission.getReadPermission(StepsRecord::class),
    HealthPermission.getReadPermission(RestingHeartRateRecord::class),
)
try {
    healthConnectClient.permissionController.requestPermissionsActivity(permissions)
} catch (e: SecurityException) { /* 用户拒绝，引导重开 */ }

    ④ 读取睡眠（分段：深睡/浅睡/REM/清醒）：

    val response = healthConnectClient.readRecords(
    ReadRecordsRequest(
        SleepSessionRecord::class,
        timeRangeFilter = TimeRangeFilter.between(today0, now)
    )
)
response.records.forEach { session ->
    session.stages.forEach { stage ->   // 每段含 startTime/endTime
        when (stage.stageType) {
            SleepSessionRecord.STAGE_TYPE_DEEP   -> deepMin += stage.duration()
            SleepSessionRecord.STAGE_TYPE_LIGHT  -> lightMin += stage.duration()
            SleepSessionRecord.STAGE_TYPE_REM    -> remMin += stage.duration()
            SleepSessionRecord.STAGE_TYPE_AWAKE  -> awakeMin += stage.duration()
        }
    }
}

    ⑤ 后台定时同步（WorkManager 每 30 分钟，仅在有新数据时）：

    class HealthSyncWorker(ctx: Context, params: WorkerParameters) : CoroutineWorker(ctx, params) {
    override suspend fun doWork(): Result {
        if (!hasPermission()) return Result.success()   // 授权丢失即跳过
        val data = readSleepAndHeartData()             // 读取今日/昨日数据
        api.upload("health/miband", data)              // 上传服务端归一化
        return Result.success()
    }
}
// 调度：PeriodicWorkRequestBuilder<HealthSyncWorker>(30, TimeUnit.MINUTES)

    ⑥ Play 控制台声明数据权限：Play Console → App content → Health Connect 声明读取的数据类型，与 Manifest 一致。

    3.3 iOS（Apple HealthKit）¶

    import HealthKit

let healthStore = HKHealthStore()

// ① 请求授权（睡眠分析 + 心率 + 步数）
let types: Set<HKObjectType> = [
    HKObjectType.categoryType(forIdentifier: .sleepAnalysis)!,
    HKObjectType.quantityType(forIdentifier: .heartRate)!,
    HKObjectType.quantityType(forIdentifier: .restingHeartRate)!,
    HKObjectType.quantityType(forIdentifier: .stepCount)!,
]
healthStore.requestAuthorization(toShare: [], read: types) { ok, _ in }

// ② 读取睡眠（按日聚合）
let sort = NSSortDescriptor(key: HKSampleSortIdentifierEndDate, ascending: false)
let query = HKSampleQuery(
    sampleType: HKObjectType.categoryType(forIdentifier: .sleepAnalysis)!,
    predicate: HKQuery.predicateForSamples(withStart: startOfDay, end: Date()),
    limit: 100, sortDescriptors: [sort]
) { _, samples, _ in
    (samples as? [HKCategorySample])?.forEach { sample in
        // sample.value: HKCategoryValueSleepAnalysis.asleepDeep / .asleepREM / .asleepCore / .awake
    }
}
healthStore.execute(query)

    注意：小米运动健康在 iOS 上以「小米运动健康」名义写入睡眠到 HealthKit（来源标识 source 会显示），读取时按来源过滤即可（HKSourceQuery 或 sample 的 sourceRevision.source.name）。

    3.4 手环通知（穿戴提醒）——无需厂商 API¶

    原理：手环由「小米运动健康」App 控制，该 App 会把手机系统通知镜像到手环。

    我们要做的只有两件事：

    1. 发标准系统通知（Android）：
    val notification = NotificationCompat.Builder(context, "health_remind")
    .setSmallIcon(R.drawable.ic_noti)
    .setContentTitle("久坐提醒")
    .setContentText("已经坐 1 小时啦，站起来活动 2 分钟吧 🏃")
    .setContentIntent(activityIntent)
    .setAutoCancel(true)
    .build()
NotificationManagerCompat.from(context).notify(REMIND_ID, notification)
    1. 引导用户在手环侧打开镜像（设置页提供图文引导）：
    小米运动健康 App → 我的 → 手环设备 → 通知与提醒 → 应用通知提醒
  → 找到「AI 健康伴侣」→ 打开开关

    App 侧要做： - 引导页：授权系统通知权限（Android 13+ 需 POST_NOTIFICATIONS 运行时权限） - 绑定引导页：检测未开启时弹出"如何让手环收到提醒"图文教程 - 通知免打扰：遵循系统「勿扰模式」+ 22:00-08:00 静默策略（对接 SRS FR-NOTIFY-05）

    限制（需在产品上说明）： - 手环只支持震动 + 文案，不支持自定义按钮交互 - 通知文案长度建议 ≤ 40 字（手环屏显示限制） - 无法从我们 App 直接控制手环震动模式（厂商能力未开放）

    3.5 验收清单（对应测试版验收风格）¶

    • [ ] 小米手环 9（+7/8 抽测）睡眠分段（深/浅/REM/清醒）与小米运动健康 App 一致
    • [ ] 心率、静息心率、步数同步正确；来源标识显示手环设备
    • [ ] 30 分钟后台自动同步，省电（无异常唤醒）
    • [ ] 用户取消授权后 24h 内停止拉取并清除本地数据
    • [ ] 久坐提醒：App 发通知 → 手环 5s 内震动
    • [ ] 22:00-08:00 静默时段手环不震动
    • [ ] 深色/浅色模式适配（原型已实现）
    • [ ] Android 8.0–15 / iOS 16–18 兼容性抽测

    4. 数据字段映射（手环 → 七要素）¶

    我们的字段（SRS） Health Connect 类型 HealthKit 类型 手环侧来源
    睡眠时长/深睡/浅睡/REM/清醒 SleepSessionRecord + stage sleepAnalysis 分段 小米手环睡眠监测
    静息心率 RestingHeartRateRecord restingHeartRate 小米手环
    心率（分钟级） HeartRateRecord heartRate 小米手环
    HRV（心率变异性） HeartRateVariabilityRecord heartRateVariabilitySDNN 手环 6+（夜间自动）
    每日步数 StepsRecord（aggregate） stepCount 手环计步
    站立/久坐时长 ActivityCardinalityRecord（支持度因版本而异） 无 手环；不支持则先降级为"久坐提醒"联动

    手环 9 的 HRV/压力等进阶指标部分未开放到 Health Connect，V1.0 先消费已开放字段，其余以「睡眠质量分 + 心率」推算（与 AI 归因逻辑衔接）。

    5. 客户端交互设计（对接原型页面）¶

    原型位置 交互
    首次引导（onboard） 增加"连接设备"步骤：检测 Health Connect / HealthKit → 一键跳授权
    我的/设置（profile） 设备列表：小米手环（来源：Health Connect），含"重新授权/解除"
    睡眠健康（sleep） 数据来源角标「小米手环」；无设备时走手动记录（FR-SLEEP-01 降级路径）
    设置（FR-AUTH-06） 手环通知开关 + 引导图文（§3.4）
    通知中心（notif） 穿戴送达/点击埋点（FR-NTF-07）

    7. 风险与合规¶

    风险 应对
    用户不同意健康授权 引导文案强调"仅读取，不上传第三方"，提供手动记录降级路径
    授权撤销 每次同步前检查；撤销后 24h 内清除本地副本
    数据为"小时/分钟级"及时性 睡眠在次日早同步（睡前数据已完整）；明确"非医疗设备"免责声明
    Play 商店审核 隐私政策 + Health Connect 声明 + 数据用途说明；避免写入误导性健康结论
    Health Connect 国内可用性 小米/红米系统内置；国产 ROM 需引导安装 Health Connect APK（google Play 版）
    手环通知被系统省电策略杀掉 引导用户加白名单（MIUI/HyperOS 自启动 + 后台耗电管理）
